1 🏗️ Arquitectura Básica del Ecosistema

Informatica PowerCenter se divide en herramientas cliente (Client Tools) que interactúan con el repositorio y el servidor de integración.

  • Repository Manager: Para administrar carpetas, permisos y metadatos.
  • Designer: Donde se desarrolla la lógica de transformación (Mappings, Mapplets). Contiene:
    • Source Analyzer: Para importar orígenes (Tablas, Flat Files).
    • Target Designer: Para crear o importar destinos.
    • Mapping Designer: El "lienzo" donde conectas orígenes, transformaciones y destinos.
  • Workflow Manager: Donde se configuran las sesiones de ejecución (conexiones a BD, rutas de archivos).
  • Workflow Monitor: Para visualizar la ejecución, leer logs y ver estadísticas de carga (Applied/Affected rows).

2 📄 Tablas Relacionales vs. Archivos Planos (Flat Files)

Al integrar datos, Informatica trata a las Tablas y a los Archivos de manera muy distinta:

Característica Tablas Relacionales (Oracle/SQL) Archivos Planos (Flat Files)
Metadatos Autodescriptivos. Al importar, Informatica lee nombres de columnas y tipos automáticamente. No descriptivos. El desarrollador debe definir explícitamente columnas, tipos y longitudes.
Conexión Vía ODBC / Cadenas de conexión relacionales. Vía variables de entorno del servidor (Rutas físicas).
Formatos Tablas, Vistas, Sinónimos. Delimitados (Coma, Pipe, Tab) o de Ancho Fijo.

Tipos de Archivos Planos:

  • 1. Delimited (Delimitados): Los campos están separados por un carácter específico (ej. ,, |, ;). Ejemplo: .csv.
  • 2. Fixed-Width (Ancho Fijo): Los campos tienen una longitud de bytes estrictamente definida (ej. Nombre del byte 1 al 20, Edad del 21 al 23). Ejemplo: .dat o .txt legacy.

3 ⚙️ Configuraciones Críticas en Designer

Importar Source (Archivo Plano)

  1. Ir a Source Analyzer → Source → Import from File.
  2. En el Wizard, seleccionar Delimited o Fixed-Width.
  3. Si tiene cabeceras, marcar:
    ☑ Import field names from first line.
  4. ⚠️ Práctica Crítica: Ajustar la Precisión (Length) de las columnas tipo String. Por defecto viene muy corta (ej. 10) y trunca datos. Cámbiala a 100 o 255.

Configurar Target (Exportar Cabeceras)

Por defecto, Informatica NO imprime los nombres de las columnas en el archivo de salida.

Solución en Target Designer:
  • Doble clic en la tabla de destino.
  • Ir a la pestaña Table.
  • Clic en el botón Advanced.
  • En Header Options seleccionar Output Field Names.

4 🚀 Escenarios de Integración (Session-07)

File to DB

Source: Flat File (customers_ff.txt).

Transformación: Pasa a través del Source Qualifier. Se pueden aplicar reglas de limpieza.

Target: Tabla Relacional en Oracle.

Nota: Asegúrate de configurar la conexión relacional de BD en el Workflow Manager.

DB to File

Source: Tabla en Oracle.

Transformación: Lógica de negocio / Extracción de reportes.

Target: Flat File (orders_ff.csv).

Nota: Configura las Header Options en Designer para que el CSV tenga títulos.

File to File

Source: Archivo Plano (ej. .dat legacy).

Target: Archivo Plano (ej. .csv limpio).

Nota: Útil para estandarización, encriptación o limpieza antes de la ingesta final.

5 📂 Variables de Entorno del Servidor (Workflow Manager)

¡Atención! Este es el punto donde ocurren el 90% de los errores. Informatica busca los archivos en el servidor donde está instalado, NO en tu computadora local. Nunca hardcodees rutas absolutas como C:\archivos\....

Utiliza siempre las variables de sistema de Informatica:

  • $PMSourceFileDir\ Ruta predeterminada del servidor para buscar archivos de ORIGEN.
  • $PMTargetFileDir\ Ruta predeterminada del servidor para depositar archivos de DESTINO.
  • $PMCacheDir\ Ruta donde se guardan cachés temporales y archivos para Lookups (LKPFILES).

Pasos en Workflow Manager:

  1. Doble clic en la Session → Pestaña Mapping.
  2. Seleccionar el origen/destino en el panel izquierdo.
  3. Source file directory: $PMSourceFileDir\
  4. Source file name: archivo.csv (¡Incluir extensión exacta!).

6 🐛 Troubleshooting (Errores Comunes y Soluciones)

FR_3000 Error opening file... No such file or directory

Causa: Informatica no encuentra el archivo en la ruta especificada en el servidor.

Solución Check-list:
  1. ¿El archivo está físicamente en el servidor dentro de la carpeta apuntada por $PMSourceFileDir?
  2. ¿El nombre del archivo está bien escrito en las propiedades de la sesión (respetando mayúsculas/minúsculas y la extensión)?
  3. Si es un archivo usado en un Flat File Lookup, ¿lo moviste a la carpeta de caché $PMCacheDir?

Los datos se cortan o salen NULL

Causa: La longitud del puerto en el Source Qualifier es menor que el dato entrante real.

Solución: Ve al Source Analyzer, aumenta la precisión de esa columna (ej. de 10 a 255), guarda el repositorio y propaga el cambio al Target.

Se omite la primera fila de datos

Causa: Configuración incorrecta en las filas a saltar al leer.

Solución: En Workflow Manager → Mapping → Source Properties, revisa Number of initial rows to skip. Si tiene 1 fila de cabecera, debe ser 1.

7 🛠️ Repaso Breve: Transformaciones Básicas (Archivos)

Source Qualifier (SQ)

Siempre acompaña al origen. Convierte los tipos de datos del archivo o de la BD a tipos de datos nativos de Informatica.

Expression (EXP)

Transformación Pasiva. Ideal para concatenar strings, limpiar espacios (LTRIM(RTRIM())), o crear columnas derivadas.

Filter (FIL)

Transformación Activa. Deja pasar solo las filas que cumplen una condición explícita (Ej. SALARY > 50000).

Sorter (SRT)

Transformación Activa. Ordena los datos. Muy útil marcando Select Distinct = True para eliminar duplicados de un Flat File.
